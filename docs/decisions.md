# Решения

Коротко: что решено, почему, когда. Подробное исследование вариантов:
[research/windows-aec-application-design.md](research/windows-aec-application-design.md).

## Обработка звука

**AEC3 из webrtc-audio-processing 2.1 (2026-09-11).** Лучшее доступное подавление без GPU и сети.
Библиотеки нет в Conan Center: локальный рецепт в `conan-recipes/`. Рецепт пинит abseil 20240722
(более новые убрали `absl::Nullable`) и добавляет в библиотеку
`api/audio/echo_canceller3_factory.h`, которой нет в тарболе freedesktop: без неё
`EchoCanceller3Config` не передать через публичный API. NVIDIA Maxine AEC снят с поддержки в AFX
SDK 3.0 и в план не входит.

**RNNoise как шумоподавитель по умолчанию (2026-09-12).** На корпусе записей NS из WebRTC давил
клавиатуру и мышь на 5 dB, RNNoise на 18 dB при той же потере речи (docs/measurements.md). Цена:
один кадр задержки (10 ms) и рецепт Conan со своим CMakeLists (тарболл 0.2 собирается autotools,
на MSVC нужны `__SSE2__`/`__SSE4_1__` вручную). NS WebRTC остался доступен ключом `ns` стадии
`webrtc`.

**Стадии и цепочка из конфига.** Бэкенд меняется конфигом, каждая возможность (aec, ns, ...)
объявляется одной стадией. Стадии линкуются статически; загрузка из DLL потребует своего
`StageParams` вместо `toml::table` в `IStage::init`.

**Reference по QPC-меткам, а не по позициям устройств.** Метки пакетов WASAPI дают общую шкалу
для микрофона и loopback; дрейф измеряется наклоном индекс/время. Читать reference прямо по
предсказанию таймлайнов нельзя (джиттер меток ломает AEC3, docs/measurements.md): позиция ведётся
непрерывно, дрейф отрабатывается проскальзыванием на сэмпл (2026-09-12). Адаптивный ресемплинг
reference отложен: по бенчмарку он дал бы 1.4 dB только на широкополосном сигнале.

**reference_lead_ms = 5 (2026-09-12).** Ревью показало, что AEC3 не вычитает эхо, которое приходит
раньше поданного reference; при lead 20 ms и задержке динамик -> микрофон 32 ms (эта машина) запас
был 12 ms, на USB-ЦАП его не было бы. Замер на устройствах: loopback отдаёт данные раньше метки, и
`refMissing` = 0 даже при lead 0, так что большой запас не нужен (docs/measurements.md).

**Таймлайн: регрессия по окну якорей (2026-09-12).** Оценка по первому и последнему якорю скакала
на границе 2 с и навсегда смещалась после потери сэмплов в кольце; регрессия по 512 якорям даёт и
частоту, и индекс без джиттера отдельной метки, потеря сэмплов начинает таймлайн заново.

**Детектор стерео AEC3 выключен (2026-09-12).** С `detect_stereo_content = true` смена характера
контента (моно-голос <-> стереомузыка) пересоздавала BlockProcessor в mic-потоке и сбрасывала
адаптивный фильтр. Reference всегда двухканальный; бенчмарк не изменился (docs/measurements.md).
Альтернатива `reference_channels = 1` отвергнута: моно-сумма не моделирует разные пути от двух
колонок.

**Reference необязателен (2026-09-12).** Пропавшие колонки (Bluetooth уснул, наушники отключили)
раньше означали серию неудачных стартов и Discord без микрофона; теперь цепочка идёт без
reference, а loopback переоткрывается по таймеру и по уведомлению об устройствах.

**Ключи стадий через StageParams (2026-09-12).** `value_or` глотал опечатки и неверные типы
(`aec = "yes"` давало true). Теперь тип и диапазон - ошибка, непрочитанный ключ - предупреждение,
как у `[engine]`. Это же будущая C-граница для стадий-плагинов.

**Выход: растяжение кадра на 1-4 сэмпла и выброс излишка разом.** Часы микрофона и выхода
расходятся, запас в кольце держит регулятор; большой излишек после подвисаний выбрасывается с
кроссфейдом, потому что регулятор убирал бы его десятки секунд.

**Микрофон по требованию (2026-09-12).** Движок держал физический микрофон постоянно: индикатор
микрофона Windows горел, Yeti был занят и вне звонков. Признак «кто-то слушает» берётся из
аудиосессий на микрофоне кабеля (`IAudioSessionManager2` видит сессии всех процессов, как
индикатор Windows), а не из драйвера: без переустановки драйвера и без IOCTL. Цена: до секунды
тишины в начале звонка плюс сходимость AEC3; уведомления `IAudioSessionNotification` вместо
опроса раз в секунду пока не нужны.

## Драйвер

**Свой кабель вместо VB-Cable (этап 4b).** Нужен контроль задержки: prime 10 ms и отброс backlog'а
при старте чтения дали 55 ms вместо 106 ms и 1007 ms. Цена: test-signing на машине разработки,
для других пользователей attestation-подпись или VB-Cable (выбирается в меню как любой выход).

**Кабель без узлов volume/mute (2026-09-12).** Узлы из образца только хранили значения; вдобавок
обе топологии писали в один и тот же регистр (node 0 общего `CSimpleAudioSampleHW`), так что
применять их в кольце было бы неверно. Без аппаратных узлов audio engine применяет громкость сам.

**Позиции кабеля на каждом тике DPC (2026-09-12).** В образце позиции двигались раз в
notification interval, и после прайма запас в кольце был 1-4 байта: порядок DPC двух сторон
решал, будет ли щёлкать. Теперь сдвиг каждую миллисекунду, запас 9 ms при том же prime 10 ms
(увеличение prime до 20 ms отвергнуто: +10 ms задержки).

**Петля с кабелем определяется по имени адаптера и шине ROOT/SWD (2026-09-12).** Ревью предлагало
PKEY_Device_ContainerId, но у всех программных устройств он общий нулевой (проверено на
endpoint'ах этой машины).

## Код и потоки

**Pipeline отдельно от Engine (2026-09-12).** Весь realtime без устройств проверяется
детерминированной симуляцией; Engine только соединяет WASAPI с Pipeline.

**SeqLock вместо spin-lock (2026-09-12).** Аудиопотоки с MMCSS никогда не ждут UI-поток; данные
в relaxed-атомиках (схема Boehm), чтение не является гонкой данных.

**Файл состояния отдельно от конфига (2026-09-12).** Приложение не переписывает конфиг: toml++
при сохранении терял комментарии шаблона, а неатомарная запись при сбое оставляла пустой конфиг.

**UTF-8 кодовая страница через манифест (2026-09-12).** `path::string()` и `path(std::string)` в
MSVC идут через ANSI-страницу: кириллица в пути ломалась на системах не с 1251.

## Сборка

**Conan 2 через cmake-conan и домашнюю папку проекта `.conan2` (2026-09-12).** Глобальный конфиг
Conan на машине разработки корпоративный (недоступный remote ломает разрешение графа); сборка от
него не зависит. Профиль выводится из компилятора, который нашёл CMake. Версии и ревизии в
`conan.lock`.

**Статический CRT, PDB в Release, минидампы (2026-09-12).** Exe запускаются без VC++
Redistributable; падение у пользователя разбирается по дампу и PDB той же сборки.

**clang-format + узкий clang-tidy (2026-09-12).** Проверки, которые на DSP-коде дают шум (magic
numbers, narrowing float/int, флаговые enum в анализаторе), отключены с объяснением в
`.clang-tidy`; остальное держится в 0 замечаний (`scripts/check.ps1`, pre-commit hook,
`scripts/ci.ps1`).
