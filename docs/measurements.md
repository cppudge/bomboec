# Замеры

Машина разработки: микрофон Yeti Orb (USB), колонки Sound Blaster Z, по умолчанию capture
"Microphone (NVIDIA Broadcast)" (виртуальный, raw mode не принимает, сам обрабатывает звук: для
записей нужен физический микрофон).

## Устройства (2026-09-11, bomboec-rec)

| Что | Значение |
|---|---|
| джиттер QPC-меток пакетов Yeti | до 0.2 ms |
| джиттер меток loopback | до 0.03 ms |
| дрейф Yeti к QPC | около +23 ppm |
| дрейф колонок (Sound Blaster) к QPC | около -117 ppm |
| относительный дрейф микрофон / колонки | около 140 ppm |
| capture-сторона кабеля к QPC | 0 ppm |

Loopback без активных render-потоков не отдаёт ни одного пакета (`bomboec-rec --no-keepalive`).

Свойства endpoint'ов (2026-09-12, перечисление без открытия потоков): у обоих концов bomboec Cable
адаптер "bomboec Cable", шина ROOT; у Steam Streaming Speakers ROOT; у Yeti USB; у Sound Blaster
HDAUDIO. ContainerId у кабеля, Steam и части endpoint'ов Sound Blaster один и тот же нулевой
`{00000000-0000-0000-FFFF-FFFFFFFFFFFF}`, поэтому концы кабеля по нему не отличить.

## Кабель и задержка (2026-09-11)

| Путь | До | После |
|---|---|---|
| Speakers кабеля -> Microphone кабеля | 1007 ms (backlog render-стороны оставался в задержке) | prime 10 ms: backlog отбрасывается при старте чтения |
| Yeti -> Speakers кабеля | 106 ms (буфер WASAPI выхода заполнялся до краёв) | около 55 ms: целевое заполнение 20 ms, запас в кольце 10 ms |

Чирп через кабель: корреляция 0.91, без пропусков пакетов (этап 4b). Задержка измерялась
кросс-корреляцией записей `bomboec-rec` (микрофон Yeti, loopback Speakers кабеля; движок с
пустой цепочкой, чирп `bomboec-play` в Sound Blaster на -18 dB).

## Задержка эха и reference_lead_ms (2026-09-12, bomboec-run)

Шум 100-6000 Hz из Sound Blaster на -14 dB, Yeti в метре от колонок, `aec delay` из статистики
AEC3 (оценка задержки между поданным reference и эхом в микрофоне), по 30 с на вариант:

| `reference_lead_ms` | `aec delay` | `refMissing` |
|---|---|---|
| 20 | 12 ms | 2 |
| 10 | 16-24 ms | 1 |
| 5 | 28 ms | 1 |
| 0 | 28-32 ms | 1 |

Задержка динамик -> микрофон на этой машине около 32 ms; при lead 20 запас причинности AEC3
был 12 ms, на выходе с малой задержкой (USB-ЦАП) его не осталось бы вовсе. За 150 с при lead 0
(полный цикл относительного дрейфа 140 ppm, 17 ms) `refMissing` = 0: loopback отдаёт данные
раньше их метки, запас lead на доставку не нужен. Умолчание снижено до 5 ms.

## Симуляция конвейера (2026-09-12, tests/test_pipeline*.cpp)

Часы, джиттер и дрейф как у устройств выше; 60 с.

| Что | Чтение reference прямо по таймлайнам | Непрерывная позиция |
|---|---|---|
| кадров с разрывом reference | 95 % | 6.7 % (ровно дрейф 140 ppm) |
| максимальный скачок | 22 сэмпла | 1 сэмпл |
| размах ошибки выравнивания | 22.9 сэмпла | 4.2 сэмпла |
| подавление эха AEC3, белый шум | 0.6 dB | 11.6 dB |

Подавление эха AEC3 через конвейер по видам искажения (бенчмарк `[aec-benchmark]`, эхо 30 ms,
ослабление 0.5, последние 10 с из 40; с отключённым детектором стерео AEC3 и регрессией таймлайна
по окну якорей, 2026-09-12, цифры те же):

| Сигнал | Идеальные часы | Только джиттер | Только дрейф | Джиттер и дрейф |
|---|---|---|---|---|
| белый шум 0-24 kHz | 13.0 dB | 13.0 dB | 11.6 dB | 11.6 dB |
| шум 0-4 kHz | 17.6 dB | 17.6 dB | 17.6 dB | 17.6 dB |

Джиттер меток больше ничего не стоит; остаток на широкополосном сигнале даёт проскальзывание на
сэмпл при дрейфе (его убрал бы адаптивный ресемплинг reference). На белом шуме полное подавление
ограничено и при идеальных часах: линейный фильтр AEC3 работает только в нижней полосе.

## Корпус эталонных записей (2026-09-12, tests/corpus, тест `[corpus]`)

Yeti Orb и Sound Blaster Z, шум 100-6000 Hz из колонок на -14 dB, через Pipeline с цепочкой
шаблона (AEC3 + NS high, lead 5 ms). Подавление = RMS mic минус RMS out на сегменте, выход
выровнен по задержке конвейера (около 20 ms по огибающим):

| Сценарий | mic | out | Подавление |
|---|---|---|---|
| тишина комнаты | -50.4 dBFS | -72.1 dBFS | 21.7 dB |
| бытовой шум (клавиатура, мышь) | -23.9 dBFS | -29.1 dBFS | 5.2 dB |
| музыка, человек молчит (эхо) | -28.2 dBFS | -68.6 dBFS | 40.4 dB |
| только речь | -29.0 dBFS | -30.5 dBFS | 1.5 dB потери |
| музыка и речь (double-talk) | -21.8 dBFS | -24.4 dBFS | 2.6 dB |
| take1 (2026-09-11): эхо / double-talk / речь | | | 28.9 / 3.3 / 2.7 dB |

На double-talk речь громче эха, поэтому общее подавление мало по построению: порог 2 dB, а
регрессию ловит сравнение с базовым значением.

Сравнение шумоподавителей на том же корпусе (`BOMBOEC_CORPUS_CONFIG`), dB:

| Сегмент | без NS | WebRTC NS high | RNNoise | RNNoise + 20 % сухого |
|---|---|---|---|---|
| тишина комнаты | 7.6 | 21.7 | 39.3 | 21.6 |
| клавиатура, мышь | 5.1 | 5.2 | 18.3 | 16.3 |
| эхо (музыка) | 22.0 | 40.4 | 45.3 | 35.7 |
| только речь (потеря) | 1.5 | 1.5 | 1.6 | 3.5 |
| double-talk | 2.2 | 2.6 | 2.4 | 4.0 |
| take1: эхо / double-talk / речь | 18.6 / 3.3 / 2.5 | 28.9 / 3.3 / 2.7 | 33.7 / 3.4 / 2.7 | 31.1 / 4.9 / 3.9 |

RNNoise давит клавиатуру втрое сильнее при той же потере речи; в шаблоне он заменил NS WebRTC.
Смесь с сухим сигналом (последняя колонка, сухой сигнал задержан на кадр сети) теряет 2 dB речи:
сеть меняет фазу, и сложение частично гасит голос. Ключ mix из стадии убран.

### Удары и щелчки (2026-09-12, сценарий `transients`)

20 с стуков по столу, щелчков ручкой, кружки и стойки без речи и музыки, 43 события (кадры 10 ms
громче медианы сегмента на 15 dB). Метрика по событиям: пик микрофона минус пик выхода.
Разбор остатка (scratchpad, `bomboec-proc --csv` со столбцом vad): проходят громкие удары с резкой
атакой (медиана 26 dB за 1 ms, пик -10 dBFS, спектр 1-12 kHz), на них VAD RNNoise 0.9-1.0;
глухие удары (низкие частоты, атака 7 dB/ms) RNNoise давит на 48 dB ниже 200 Hz. Речь на
началах слов нарастает на 8.6 dB/ms (p90 14, максимум по всем громким миллисекундам 19.7).

| Метрика | AEC3 + rnnoise | + transient (rise 20 dB/ms, level -30 dBFS, -20 dB, hold 60 ms) |
|---|---|---|
| медиана подавления удара | 9.4 dB | 31.4 dB |
| худший удар | 0.8 dB | 20.2 dB |
| самый громкий остаток на выходе | -10.6 dBFS | -29.3 dBFS |
| клавиатура, мышь (сегмент noise) | 18.3 dB | 22.7 dB |
| только речь (потеря) | 1.6 dB | 1.6 dB |
| double-talk | 2.4 dB | 2.6 dB |
| take1: эхо / double-talk / речь | 33.7 / 3.4 / 2.7 | 33.7 / 3.4 / 2.7 |

На живой речи стадия заметно портила голос, хотя потеря RMS речи в корпусе не изменилась (1.6 dB):
эта метрика слепа к порче. Поэтому появились смеси (ниже), и по ним гейт выключен в шаблоне.

### Смеси: чистая речь плюс помеха (2026-09-12, `[[mix]]`)

Чистая речь (сценарий speech) складывается с отдельно записанным шумом или с эхом (mic.wav и
ref.wav сценария music), выход выравнивается по лагу и сравнивается с чистой речью на её кадрах
(громче 10-го процентиля уровней на 15 dB): lsd - среднее |out - clean| по 24 логарифмическим
полосам 100 Hz - 12 kHz, dB (в скобках то же против чистой речи, прошедшей ту же цепочку без
помехи); провалы - доля речевых кадров ниже медианы на 6 dB и больше; подавление - энергия входа
к энергии выхода на кадрах без речи.

| Смесь | SNR входа | шаблон: lsd / провалы / подавление | + transient 20 dB/ms | + transient 30 dB/ms |
|---|---|---|---|---|
| речь без помех | - | 6.8 (0) / 10.6 % / 13.4 dB | то же, 0 срабатываний | то же |
| речь + клавиатура | -1.7 dB | 8.0 (2.4) / 11.7 % / 21.8 dB | 9.5 (4.0) / 20.3 % / 19.1 dB, 35 сраб. | 8.4 (2.9) / 14.5 % / 14.5 dB, 16 сраб. |
| речь + стуки | -3.1 dB | 8.9 (3.1) / 12.0 % / 21.0 dB | 10.8 (6.5) / 22.5 % / 30.0 dB, 38 сраб. | 9.1 (3.3) / 13.3 % / 24.6 dB, 9 сраб. |
| речь + эхо музыки на уровне речи | 1.9 dB | 19.8 (15.4) / 34.9 % / 37.2 dB | то же | то же |
| речь + эхо на 10 dB тише | 11.9 dB | 9.1 (5.8) / 11.8 % / 35.0 dB | 9.4 (6.1) / 13.4 % | то же |
| живая речь (speech-call) без помех | - | 3.3 (0) / 3.8 % / 12.9 dB | 5.0 (0) / 11.0 %, 5 сраб. | 0 сраб. |
| живая речь + клавиатура | | 4.8 (2.1) / 4.2 % / 22.8 dB | 8.3 (6.9) / 18.3 % | |
| живая речь + стуки | | 5.5 (3.1) / 4.9 % / 26.5 dB | 9.7 (8.3) / 20.0 % | |
| живая речь + эхо на 10 dB тише | | 7.7 (5.2) / 7.8 % / 28.2 dB | 8.5 (6.1) / 12.4 % | |

Выводы. На живой речи (пик -6 dBFS, как в звонке) гейт срабатывает и без помех: 5 раз за 30 с,
провалы речи 3.8 % -> 11 %; это и слышал пользователь. Громкий голос цепочка сама портит
меньше, чем тихое чтение (lsd 3.3 против 6.8): уровень микрофона имеет значение для RNNoise.
Гейт удваивает провалы речи: щелчок во время слова режет и слово, при 30 dB/ms вред
меньше, но и пользы почти нет; в шаблоне стадия выключена. Сама цепочка на чистой речи проваливает
10 % кадров (тихие согласные после RNNoise и HPF). Эхо на уровне речи: AEC3 в double-talk давит
голос на 15 dB по спектру и проваливает треть кадров, тогда как метрика double_talk сценария
(2.4 dB общего подавления) этого не видит; при эхе на 10 dB тише речи порча 5.8 dB. Следующий
рычаг качества: настройка подавителя AEC3 под double-talk (nearend tuning, dominant nearend) -
сделано, см. ниже.

### Шаблон после настройки (2026-09-12, `docs/research/2026-09-12-ns-quality.md`)

Свипы по корпусу нашли три рычага: свой фильтр высоких частот 90 Hz **перед** AEC3 (ключ hpf
стадии webrtc не работает - APM держит свой HPF, пока включён AEC), прозрачный подавитель AEC3
для ближнего голоса и проверка гармоничности в гейте ударов. Первые два вошли в шаблон, гейт
остался выключенным. Все числа и отвергнутые варианты - в отчёте.

| Метрика | было | стало |
|---|---|---|
| чистая речь: lsd / провалы | 6.8 / 10.6 % | 5.1 / 8.9 % |
| речь + эхо на уровне речи | 19.8 / 34.9 % | 13.9 / 24.1 % |
| речь + эхо на 10 dB тише | 9.1 / 11.8 % | 7.5 / 10.8 % |
| живая речь + эхо на 10 dB тише | 7.7 / 7.8 % | 5.9 / 6.0 % |
| эхо (музыка) / take1 эхо | 45.3 / 33.7 dB | 50.5 / 36.1 dB |
| удары (медиана / худший остаток) | 9.4 dB / -10.6 dBFS | 12.4 dB / -11.3 dBFS |
| остаток эха на паузах в double-talk | -46 dBFS | -37 dBFS |

Гейт ударов с проверкой гармоничности (выключен, +4 ms задержки): удары 31.9 dB, худший остаток
-29.6 dBFS, а ложных срабатываний на живой речи больше нет (провалы 4.7 % против 11.0 % у гейта
без проверки и 4.3 % у цепочки с той же задержкой).

### Гейт ударов внутри rnnoise (2026-09-14, `docs/research/2026-09-14-transient-gate.md`)

Тест смесей теперь выравнивает выход до сэмпла (было до кадра, и задержка 4 ms гейта считалась
порчей голоса, а lsd смесей с эхом был завышен на 3 dB). Гейт перенесён в стадию rnnoise без своей
задержки, детектор ловит атаки, размазанные APM на 2 ms, а режим duck прижимает удар к слышимому
фону вместо удержания на -20 dB. `gate = true` (в шаблоне пока false):

| Метрика | без гейта | стадия transient, hold (+4 ms) | gate = true |
|---|---|---|---|
| провалы: живая речь / + стуки / + клавиатура | 3.9 / 5.0 / 4.7 % | 5.5 / 13.6 / 14.2 % | 4.4 / 7.4 / 6.6 % |
| провалы: чтение + стуки / + клавиатура | 9.7 / 10.3 % | 22.1 / 21.1 % | 11.5 / 12.1 % |
| удары: медиана / худший остаток | 12.7 dB / -11.5 dBFS | 32.6 dB / -31.5 dBFS | 37.2 dB / -33.5 dBFS |
| клавиатура (noise) | 18.8 dB | 33.4 dB | 27.2 dB |

### AEC3 на старте (2026-09-14, `docs/research/2026-09-14-aec-startup.md`)

Пока адаптивный фильтр не сошёлся (первые до 6 секунд звука в колонках, смена задержки), AEC3
считает эхо равным reference. Тихий звук в колонках, которого микрофон не слышит, резал голос на
20-50 dB. `echo_path_default_gain = 0.4` в шаблоне:

| Метрика | 1.0 (штатно) | 0.4 |
|---|---|---|
| живая речь + свой loopback -46 dBFS: провалы, 10 сдвигов reference | 2.7-6.6 %, до -80 dB | 0.2-0.7 %, до -23 dB |
| call+quiet-render: lsd против той же речи без звука | 0.87 dB | 0.22 dB |
| старт посреди громкой музыки: подавление в первую секунду (среднее / минимум) | 28.8 / 17.6 dB | 28.5 / 18.1 dB |
| music / take1 эхо | 50.5 / 36.1 dB | 54.0 / 37.5 dB |

Другие сценарии:

| Сценарий | Было | Стало |
|---|---|---|
| микрофон подвис на 200 ms, WASAPI отдал накопленное разом | задержка возвращалась к цели около 40 с | в пределах цели через 1-2 с (излишек выброшен с кроссфейдом) |
| один пакет с меткой qpc = 0 | 2 с тишины в кольце, сдвиг таймлайна на 2 с | ресинхронизация таймлайна, задержка выхода не меняется, reference идёт свободным ходом (раньше два кадра с нулевым reference и скачок позиции) |
| loopback пропал на 5 с | — | 500 кадров с нулевым reference, после возвращения выравнивание восстановлено за секунду |
| эхо 12 ms при lead 5 ms | при lead 20 ms эхо опережало reference: 1.3 dB (офлайн-эксперимент ревью) | 13 dB, как при эхе 30 ms |
| якоря с джиттером ±0.2 ms | оценка частоты по первому и последнему якорю: до 40 ppm ошибки за 10 с, индекс по последней метке ±10 сэмплов | регрессия по 512 якорям: 8 ppm, индекс в пределах 1 сэмпла |
