# AEC3 режет голос первые секунды после старта (2026-09-14)

Ветка `research/ns-gate-2026-09-14`. Жалоба после прослушивания `recordings/listen-2026-09-14`:
в `call-alone.base.wav` между второй и третьей секундой пропадает слово «не», хотя шума там нет, и
с гейтом ударов, и без него.

## Итог

- Слово режет подавитель AEC3 (стадия `webrtc`), а не RNNoise и не гейт. В loopback записи
  `speech-call` что-то тихо играло (около -46 dBFS, в основном ниже 300 Hz), в микрофон это не
  попадало (корреляция mic/ref 0.01). С молчащим reference слово целое.
- Пока адаптивный фильтр AEC3 не сошёлся, AEC3 не знает, насколько громко колонки слышны в
  микрофоне, и считает эхо равным reference с усилением `ep_strength.default_gain` (штатно 1.0).
  Голос того же уровня, что такое «эхо», давится. Фильтр сходится только на настоящем эхе, а без
  него AEC3 через 6 секунд активного reference включает прозрачный режим. Поэтому все провалы
  в первых 6 секундах.
- Какие кадры пострадают, зависит от сдвига reference на единицы миллисекунд хаотично: от 0 до
  6.6 % кадров речи. Файлы для прослушивания делал `bomboec-proc` без сдвига (3.8 %), а
  симуляция конвейера с `reference_lead_ms = 5` попала в удачный случай (0 %). Для
  `bomboec.exe` это лотерея на каждый старт движка и на каждую смену задержки эха.
- Новый ключ стадии `webrtc`: `echo_path_default_gain`, в шаблоне 0.4. Провалы на той же записи
  4 % -> 0.3-0.7 %, эхо громкой музыки на старте давится как при 1.0, корпус не хуже.
- В корпус добавлена смесь `call+quiet-render` (звук в колонках мимо микрофона, шесть сдвигов
  reference) и порог `mix_render_max_db`: выход не должен отличаться от той же речи без этого
  звука больше чем на 0.5 dB lsd. При 1.0 было 0.87, при 0.4 стало 0.22.

## 1. Где пропадает слово

Уровень кадров 10 ms относительно входа, запись `speech-call` с её же `ref.wav` через
`bomboec-proc`:

| t, s | вход, dBFS | hpf | hpf + webrtc | rnnoise | вся цепочка | вся цепочка, ref = 0 |
|---|---|---|---|---|---|---|
| 2.63 | -30.7 | -0.5 | -26.8 | -0.8 | -38.5 | -1.0 |
| 2.66 | -29.6 | -1.5 | -29.0 | -1.6 | -44.5 | -1.7 |
| 2.69 | -29.9 | 0.4 | -30.4 | -0.2 | -52.1 | 0.2 |
| 2.78 | -30.2 | 0.2 | -29.2 | -0.5 | -37.1 | 0.1 |
| 2.87 | -36.8 | -0.0 | -24.3 | -0.4 | -35.7 | -1.6 |

Гласная «е» на -30 dBFS теряет в APM 25-30 dB, RNNoise добирает остальное: на задавленном
сигнале у него VAD падает до 0.002. Провалы (кадр речи с выходом на 6 dB тише, чем при
молчащем reference) по секундам: 1-2 с 7, 2-3 с 32, 3-4 с 8, 4-5 с 3, 5-6 с 1, дальше ни
одного.

Первые кадры слова (2.54-2.58) цепочка режет и без reference, но там не голос: больше 80 %
энергии ниже 90 Hz (толчок воздуха или стойка), основной тон появляется с 2.60 (140 Hz). Это
законная работа hpf и RNNoise.

## 2. Механизм в исходниках AEC3

- `ResidualEchoEstimator::Estimate`: пока `AecState::UsableLinearEstimate()` ложно (линейный
  фильтр ни разу не сошёлся), остаток эха оценивается нелинейно: мощность reference (для стерео
  сумма каналов) умножается на квадрат `default_gain`, плюс модель реверберации.
- `SuppressionGain`: вне состояния «говорит человек» пороги маски жёсткие (в HF эхо на 10 dB тише
  голоса уже полное подавление), а усиление выше 2 kHz ограничено усилением на 2 kHz. Поэтому
  провал широкополосный.
- `LegacyTransparentModeImpl`: если за 6 секунд активного reference (`strong_not_saturated_
  render_blocks_`) фильтр не сошёлся, включается прозрачный режим с усилением 0.01, и подавление
  пропадает. Счётчик обнуляется при смене задержки эха (`HandleEchoPathChange`, полный сброс).
- Штатные 1.0 значат «микрофон слышит колонки так же громко, как они играют». В этой комнате
  эхо громкой музыки тише reference на 6.4 dB (take1 на 14.7 dB), то есть реальное усиление
  около 0.48.

## 3. Хаос от сдвига reference

Одна и та же запись, штатное усиление, сдвиг reference относительно микрофона в `bomboec-proc`:

| сдвиг, ms | -20 | -10 | -5 | -3 | -2 | -1 | 0 | 3 | 5 | 7 | 10 | 32 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|
| провалы, % | 0 | 3.5 | 6.2 | 6.3 | 2.7 | 6.6 | 3.8 | 4.9 | 2.7 | 6.0 | 0 | 4.6 |

Худший кадр при ненулевых провалах от -42 до -80 dB. Один прогон ничего не доказывает, поэтому
смесь в корпусе гоняется с шестью сдвигами (0, 1, 2, 3, 5, 7 ms), метрики усредняются.

## 4. Что пробовал

Синтетика на полной цепочке шаблона (`bomboec-proc`):

- A: живая речь плюс reference, которого в микрофоне нет (музыка на разных уровнях или свой
  loopback записи). Провалы против того же прогона с молчащим reference.
- B: старт обработки посреди громкой музыки (5 точек старта, 3 сдвига reference, 15 случаев),
  подавление эха в первую секунду. Тут эхо настоящее, и заниженное усиление должно его пропустить.

A, провалы % / худший кадр dB:

| reference | 1.0 | 0.5 | 0.4 | 0.3 |
|---|---|---|---|---|
| музыка -22 dBFS | 0.9 / -29.3 | 0.7 / -20.2 | 0.7 / -18.0 | 0.6 / -15.4 |
| музыка -32 dBFS | 1.5 / -60.3 | 0.3 / -27.9 | 0.2 / -23.8 | 0.2 / -21.2 |
| музыка -42 dBFS | 0.7 / -27.1 | 0.4 / -14.2 | 0.2 / -11.4 | 0.0 / -5.4 |
| музыка -52 dBFS | 2.7 / -55.7 | 0.8 / -28.5 | 0.2 / -21.3 | 0.1 / -9.8 |
| свой loopback -46 dBFS | 3.8 / -53.0 | 0.5 / -24.7 | 0.3 / -15.4 | 0.3 / -13.6 |
| свой loopback, 10 сдвигов | 2.7-6.6 / до -80 | 0.4-1.3 / до -27 | 0.2-0.7 / до -23 | |

B, подавление в первую секунду (среднее / минимум по 15 случаям) и худший остаток за 100 ms:

| | 1.0 | 0.5 | 0.4 | 0.3 | 0.2 | 0.1 |
|---|---|---|---|---|---|---|
| среднее / минимум, dB | 28.8 / 17.6 | 28.5 / 17.7 | 28.5 / 18.1 | 28.1 / 18.6 | 18.6 / 10.6 | 15.8 / 10.0 |
| худший остаток, dBFS | -40.0 | -40.1 | -40.5 | -41.9 | -31.7 | -32.3 |

Между 0.3 и 0.2 обрыв: при 0.2 эхо на старте давится на 10 dB слабее. При 0.3 в одном из 15
случаев подавление 23 dB вместо 34. Выбрано 0.4, с запасом в шаг.

Не помогли:

- HMM-вариант прозрачного режима (field trial `WebRTC-Aec3TransparentModeHmm`): на своём loopback
  провалов не меньше, чем у штатного (4.8 % против 3.8 %), и нужна глобальная строка field trials
  на процесс. Прогон шёл ещё со скриптом, где воркеры переписывали общий конфиг, так что число
  ориентировочное. Ключ удалён.
- Без модели реверберации в нелинейной оценке (`model_reverb_in_nonlinear_mode = false`): голосу
  помогает как усиление 0.3, но B хуже: при 0.5 и без реверберации в первую секунду 13-15 dB в двух
  случаях из пяти. Прогон с тем же скриптом, число ориентировочное.
- Порог шума reference (`echo_model.noise_gate_power` +10 dB): ничего не меняет.

## 5. Корпус

Шаблон с `echo_path_default_gain = 0.4` против 1.0 (все проверки проходят):

| | 1.0 | 0.4 |
|---|---|---|
| music (эхо) | 50.5 dB | 54.0 dB |
| take1: эхо / double-talk / речь | 36.1 / 3.1 / 2.4 | 37.5 / 3.1 / 2.4 |
| silence / noise | 39.2 / 18.8 dB | 38.9 / 19.5 dB |
| speech-call: потеря речи | 1.1 dB | 1.2 dB |
| речь + эхо на уровне речи: lsd / провалы / подавление | 10.8 / 17.8 % / 34.2 | 10.9 / 18.0 % / 35.3 |
| речь + эхо на 10 dB тише | 7.4 / 11.1 % / 26.1 | 7.0 / 10.8 % / 26.3 |
| живая речь + эхо на 10 dB тише | 5.9 / 6.1 % / 22.5 | 5.8 / 6.1 % / 22.5 |
| call+quiet-render: lsd / провалы / против той же речи без звука | 4.1 / 6.0 % / 0.87 dB | 3.5 / 4.1 % / 0.22 dB |

Смеси с молчащим reference не меняются. С `gate = true` на новом шаблоне: удары 37.2 dB (как
было), клавиатура 30.0 dB (было 27.2 при 1.0).

Корпусная смесь поддерживает `render` (только `ref.wav` записи) и `render_shifts_ms`, а
`BOMBOEC_CORPUS_DUMP=<каталог>` пишет вход, выход и чистый прогон каждой смеси в WAV.

## 6. Что осталось

- Прозрачный режим всё так же включается через 6 секунд и сбрасывается при смене задержки. С 0.4
  окно почти безвредно, но худшие кадры на старте ещё теряют 15-23 dB. На этой записи это тихий
  хвост на -41 dBFS с энергией выше 1 kHz, там жёсткие HF-пороги подавителя.
- 0.4 подобрано под эту комнату: эхо громкой музыки тише reference на 6 dB. Если колонки
  громче или ближе к микрофону, прогнать B на новой записи музыки.
- Для прослушивания: `recordings/listen-2026-09-14/*.aec04.wav` (шаблон с 0.4) и
  `*.aec04_gate.wav` (он же с `gate = true`), рядом прежние `*.base.wav` и `*.gate_default.wav`
  на 1.0.
