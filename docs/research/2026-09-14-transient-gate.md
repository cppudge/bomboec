# Гейт ударов без задержки и точное выравнивание корпуса (2026-09-14)

Ветка `research/ns-gate-2026-09-14`, продолжение `2026-09-12-ns-quality.md`. Всё измерено офлайн
на корпусе `recordings/corpus` через `bomboec_tests "[corpus]"` с подменой цепочки
(`BOMBOEC_CORPUS_CONFIG`) и через `bomboec-proc` для разбора отдельных ударов. Метрики те же, что
в прошлом отчёте: lsd и провалы (доля речевых кадров, просевших больше чем на 6 dB) на смесях,
подавление по сегментам сценариев, медиана подавления и худший остаток на ударах.

## Итог

- Тест смесей выравнивает выход с точностью до сэмпла. Прежнее выравнивание до кадра завышало
  порчу голоса (lsd смеси с эхом на уровне речи 13.9 -> на самом деле 10.8) и засчитывало
  задержку гейта 4 ms как порчу голоса.
- У RNNoise 0.2 задержка два кадра (20 ms), а не один; модель в проекте уже новая и большая.
  Исправлены `latencyFrames`, тест, README и приложение прошлого отчёта.
- Гейт ударов встроен в стадию rnnoise (`gate = true`): детектор на входе сети, усиление на её
  выходе. Своей задержки нет, фаза кадров сети та же, что без гейта.
- Детектор ловит атаки, которые WebRTC APM размазал на 2 ms (скачок за 2 блока >= 30 dB).
  Самые громкие удары после APM раньше проходили мимо гейта.
- Режим `duck`: удар прижимается к слышимому фону (выход сети до атаки) плюс 15 dB, не глубже
  30 dB, вместо удержания -20 dB на 60 ms. Голос поверх удара и сразу после него почти не
  страдает.

| | без гейта | стадия transient, hold (+4 ms) | `gate = true` (0 ms) |
|---|---|---|---|
| провалы: живая речь | 3.9 % | 5.5 % | 4.4 % |
| провалы: живая речь + стуки | 5.0 % | 13.6 % | 7.4 % |
| провалы: живая речь + клавиатура | 4.7 % | 14.2 % | 6.6 % |
| провалы: чтение + стуки | 9.7 % | 22.1 % | 11.5 % |
| провалы: чтение + клавиатура | 10.3 % | 21.1 % | 12.1 % |
| удары: медиана / худший остаток | 12.7 dB / -11.5 dBFS | 32.6 dB / -31.5 dBFS | 37.2 dB / -33.5 dBFS |
| клавиатура (сценарий noise) | 18.8 dB | 33.4 dB | 27.2 dB |
| остаток ударов в смеси с чтением | -14.9 dBFS | -34.0 dBFS | -39.2 dBFS |

Колонка hold - стадия `transient` из прошлого отчёта (harmonicity 0.4, lookahead 4 ms) уже с
новым детектором. В шаблоне `gate = false`: включать или нет, решает прослушивание, прошлый гейт
(ещё без проверки гармоничности) при нормальной потере уровня речи на слух портил голос.

## 1. Поправки к прошлому отчёту

Проверено по исходникам RNNoise 0.2 в `.conan2`:

- **Модель уже большая.** `rnnoise_data.h`: свёртки 65 -> 128 -> 384, три GRU по 384, выход 32
  полосы; веса int8, GRU разреженные (`*_weights_idx`), около миллиона ненулевых весов,
  `rnnoise_data.c` 4.9 МБ. Это и есть модель 2024 года, а не 85 тыс. параметров 2017-го, так что
  "новые веса как дешёвый апгрейд" из приложения не существует.
- **Задержка два кадра.** В `rnnoise_process_frame` усиление, посчитанное по новому кадру,
  применяется к спектру предыдущего (`delayed_X`, сеть заглядывает на кадр вперёд), плюс
  перекрытие окон при синтезе. Щелчок на сэмпле 100 кадра 0 выходит ровно на сэмпле 100
  кадра 2 (новый тест в `test_rnnoise.cpp`; старый тест "в следующем кадре энергии больше"
  проходил на утечке). Отсюда же сомнение в прежнем опыте со смесью dry/wet: сухой сигнал был
  выровнен на один кадр, то есть сдвинут на 10 ms; с верным сдвигом он не проверялся.
- GTCRN работает на 16 kHz с окном 32 ms, а не 20 ms.

## 2. Выравнивание до сэмпла

`estimateLagSamples` в `tests/test_corpus.cpp`: грубо по огибающим 10 ms (как было), затем
взаимная корреляция самих сигналов в пределах кадра от грубого лага по 300 самым громким кадрам
входа. Смеси сверяются с чистой речью (её цепочка пропускает). Для сценариев лаг берётся с
прогона чистой речи первой смеси и запоминается на конфиг: на тишине и эхе без речи корреляции не
за что зацепиться, а на ударах, которые убрал гейт, оценка уезжала на 9 ms.

Проверка: цепочка с гейтом, который никогда не срабатывает (rise 60, lookahead 4 ms), теперь
отличается от шаблона ровно на 4.000 ms лага, а по голосу почти не отличается (чтение 5.04 / 9.0 %
против 4.94 / 9.0 %). При выравнивании до кадра та же "одна задержка" стоила живой речи
3.33 -> 4.88 lsd.

Шаблон, те же записи, до кадра -> до сэмпла:

| смесь | lsd / провалы до кадра | до сэмпла |
|---|---|---|
| speech-alone | 5.14 / 8.9 | 4.94 / 9.0 |
| speech+keyboard | 7.77 / 11.8 | 6.24 / 10.3 |
| speech+knocks | 8.84 / 12.1 | 7.47 / 9.7 |
| speech+music-echo | 13.91 / 24.1 | 10.77 / 17.8 |
| speech+music-echo-10 | 7.49 / 10.8 | 7.41 / 11.1 |
| call-alone | 3.48 / 3.9 | 3.41 / 3.9 |
| call+keyboard | 5.03 / 4.4 | 5.04 / 4.7 |
| call+knocks | 5.47 / 5.0 | 5.52 / 5.0 |
| call+music-echo-10 | 5.85 / 6.0 | 5.88 / 6.1 |

Выводы прошлого отчёта о подавителе AEC3 и HPF это не меняет (варианты сравнивались при одной и
той же ошибке выравнивания), но абсолютная порча голоса эхом меньше, чем там написано.

**Чувствительность к фазе кадров.** Задержка 4 ms перед RNNoise без всякого гейта меняет
подавление клавиатуры в сценарии noise с 18.8 до 22.7 dB, silence 39.2 -> 41.0, music 50.5 ->
53.7, take1 36.1 -> 34.8: сеть по-разному обрабатывает щелчок в зависимости от того, где он лёг
в её окне. Разница в 2-4 dB на сценариях между цепочками с разной задержкой - шум, а не качество.

## 3. Гейт на выходе сети

Логика гейта вынесена в `src/stages/transient_gate.*` (общая для стадии `transient` и для
rnnoise). Гейт выдаёт усиление с задержкой `outputDelaySamples` относительно входа детектора; в
rnnoise это 960 сэмплов, так что lookahead до 20 ms бесплатен, а пре-ролл дописывается в ещё не
выданную часть линии усиления.

Тот же гейт (hold, depth 20, hold 60, harmonicity 0.4, lookahead 4), что стоял отдельной стадией
перед rnnoise, но на выходе сети: удары 30.8 dB против 32.5, худший остаток -30.9 против -31.5,
провалы те же, лаг выхода равен лагу шаблона. В прошлом отчёте "гейт после rnnoise" был хуже
потому, что там и детектор смотрел на выход сети с размазанной атакой.

На клавиатуре гейт перед сетью давит чуть сильнее (33.4 против 31.1 dB у hold после сети, с
детектором из п. 4), но это в пределах шума фазы кадров: одна задержка 4 ms перед сетью без гейта
даёт +3.9 dB на том же сценарии (п. 2).

## 4. APM размазывает атаку

Худший остаток на ударах оставался около -24 dBFS при любых настройках режима `duck`. Разбор по
блокам 1 ms показал, что самый громкий удар корпуса (14.87 s, пик -11 dBFS) гейт не видел вообще,
а -31 dBFS на выходе hold был хвостом release от предыдущего удара через 90 ms.

На сыром микрофоне этот удар поднимается на 38 dB за 1 ms при любой фазе блоков. На выходе стадии
webrtc (перед гейтом) атака размазана: -52 -> -31 -> -13 dBFS, первый шаг ниже `level_dbfs`,
второй 18 dB. Прошлый разбор атак делался по сырому микрофону, поэтому этого не видел.

Скачки на выходе APM (группы атак с разрывом 30 ms, уровень >= -30 dBFS; в скобках - сколько из
них с гармоничностью <= 0.4, то есть реально сработали бы):

| условие | transients | noise (клавиатура) | speech | speech-call |
|---|---|---|---|---|
| r1 >= 20 (как было) | 51 (51) | 42 (42) | 12 (2) | 19 (0) |
| r1 >= 15 | 58 (58) | 46 (46) | 36 (4) | 46 (5) |
| r1 >= 20 или r2 >= 25 | 52 (52) | 46 (46) | 16 (2) | 25 (1) |
| **r1 >= 20 или r2 >= 30** | **52 (52)** | **44 (44)** | **12 (2)** | **21 (0)** |
| r1 >= 20 или r2 >= 35 | 52 (52) | 43 (43) | 12 (2) | 19 (0) |

r1 - скачок за 1 ms, r2 - за 2 ms. Взято r2 >= 1.5 x `rise_db_per_ms`: ни одного лишнего
срабатывания на речи, плюс пропущенные удары и щелчки. Скачок за два блока через блок, который
уже сработал, не считается (иначе каждый щелчок срабатывал бы дважды). Эффект на корпусе (hold на
выходе сети): клавиатура 21.5 -> 31.1 dB, удары 30.8 -> 32.4 dB.

## 5. Режим duck

Hold гасит голос на всё удержание: одно срабатывание - это 60 ms на -20 dB и ещё около 60 ms
release до -6 dB, то есть 12 речевых кадров. 38 срабатываний клавиатуры поверх чтения давали
+11 % провалов.

Duck после атаки следит за огибающей входа (с заглядыванием на lookahead) и прижимает её к фону
до атаки плюс `margin_db`, не глубже `depth_db`; `hold_ms` - сколько после атаки гейт следит (он
ловит отскоки без своей атаки). Фон - мощность выхода стадии за 20 ms до атаки: у rnnoise это то,
что реально слышно, без шума, который сеть убрала. Фон по входу сети давал на 1 п.п. меньше
провалов, но удары на шумном фоне давил на 5 dB слабее (37.2 -> 32.5 dB, худший остаток -33.5 ->
-28.4), потому что считал фон громким там, где на выходе тишина.

Свип (гейт на выходе сети, детектор с r2; чт - чтение, жр - живая речь; провалы, %):

| вариант | жр | жр+стуки | жр+клав. | чт+стуки | удары: медиана / худший | клавиатура |
|---|---|---|---|---|---|---|
| hold, depth 20 | 5.5 | 14.2 | 14.2 | 22.5 | 32.4 / -30.9 | 31.1 |
| duck margin 10, depth 30, release 20, lookahead 4 | 4.9 | 9.7 | 7.9 | 13.6 | 37.4 / -34.4 | 27.8 |
| то же, hold_ms 30 | 4.4 | 7.5 | 6.4 | 12.3 | 36.2 / -30.7 | 26.8 |
| то же, harmonicity 0.3 | 4.4 | 8.9 | 7.5 | 13.1 | 37.4 / -34.4 | 27.8 |
| то же, lookahead 8 | 4.4 | 9.1 | 7.5 | 13.4 | 37.4 / -34.4 | 27.9 |
| то же, margin 15 | 4.7 | 8.4 | 7.2 | 12.0 | 37.4 / -34.4 | 27.4 |
| margin 15, lookahead 8 | 4.4 | 8.1 | 7.0 | 11.8 | 37.4 / -34.4 | 27.5 |
| **margin 15, lookahead 8, release 10** | **4.4** | **7.4** | **6.6** | **11.5** | **37.2 / -33.5** | **27.2** |
| margin 15, lookahead 8, release 10, harmonicity 0.3 | 4.4 | 7.4 | 6.6 | 11.5 | 37.2 / -33.5 | 25.8 |
| margin 20, lookahead 8, release 10, harmonicity 0.3 | 4.4 | 6.9 | 5.9 | 10.7 | 37.0 / -28.5 | 25.4 |
| margin 15, lookahead 8, release 10, harmonicity 0.3, hold_ms 40 | 4.3 | 6.5 | 5.9 | 11.0 | 36.2 / -29.8 | 25.5 |
| без гейта | 3.9 | 5.0 | 4.7 | 9.7 | 12.7 / -11.5 | 18.8 |

- `lookahead_ms` 8 вместо 4 убирает ложные срабатывания на чистой речи (чтение 3 -> 1, живая
  речь 3 -> 2) без потерь на ударах: окну гармоничности хватает начала голоса после атаки. В
  rnnoise это ничего не стоит.
- `margin_db` больше 15 и `hold_ms` меньше 60 ещё уменьшают провалы, но начинают пропускать
  отскоки: худший остаток -28...-30 dBFS против -33.5.
- `harmonicity_max` 0.3 в выбранной точке не меняет провалы, но забирает 1.4 dB на клавиатуре.
- `depth_db` 30 вместо 20 в duck почти бесплатен: поверх голоса глубину ограничивает фон.

Выбрано (значения по умолчанию `gate_*` в rnnoise): duck, depth 30, margin 15, hold 60,
release 10, harmonicity 0.4, lookahead 8, rise 20, level -30, preroll 2.

## Проверить на слух

Файлы для A/B (живая речь из корпуса со смешанными ударами и клавиатурой, `bomboec-proc` с шаблоном
и с `gate = true`) собираются так:

```
bomboec-proc --mic <смесь>.wav --ref recordings/corpus/speech-call/ref.wav --config <конфиг> --out <выход>.wav
```

Если голос на слух не страдает, `gate = true` можно ставить в шаблон и в `bomboec.toml` рядом с exe.
